# HomeworkChecker — AI-проверка рукописных домашних работ ОГЭ/ЕГЭ с моделью доверия

Система проверяет фотографии рукописных решений по математике: распознаёт почерк, находит ошибки ученика, отделяет
ошибки от замечаний по режиму работы (экзамен / тренировка) и решает, каким вердиктам можно верить автоматически,
а какие задачи показать куратору. Качество измерено против разметки на dev с групповой кросс-валидацией и в трёх
отложенных test-запусках, каждый — один раз по заранее зарегистрированному протоколу.

## Как это работает

```
фото тетради → обезличивание → распознавание почерка (Gemini, LaTeX) ─┐
условие (PDF/фото задачника) → распознавание условия (Gemini, кэш) ───┤
ключ ответов (data/keys/answer_key.csv) ──────────────────────────────┼→ проверка v1 (Gemini с ключом)
                                                                       │        │ отклонения
                         разметка ситуаций (tagger.py, Gemini) ←───────┘        ▼
          ситуация + режим работы (data/cards/modes.csv) → политика (rules/policy.csv, policy.py): ошибка / замечание
                                                                                 ▼
вердикты + признаки → модель доверия (логрег v5, ml/) → «уверенно» — ученику, «сомнительно» — куратору
```

1. **Распознавание** (`check.py`, шаг transcribe): страница — отдельный запрос, формулы в LaTeX, постраничный кэш.
2. **Условие** (шаг task): PDF задачника или фото листа → задачи с номерами; нужные страницы PDF; дозапрос ненайденных номеров.
3. **Проверка v1** (шаг check): модель сверяет итоговый ответ с ключом и проверяет ход решения по правилам
   LABELING_RULES.md, перечисляет отклонения.
4. **Ситуации и политика** (`tagger.py`, `policy.py`): каждое отклонение относится к одной из 113 ситуаций
   rules/policy.csv (например, «найдена не та величина в одно действие», «описка, дальше верно»); решение «ошибка /
   замечание / не упоминать» принимает таблица по режиму работы. Экспериментально: детектор «с нуля» хуже, чем v1 +
   разметка его отклонений (EXPERIMENTS.md, п. 22–23); на test3 слой не дал выигрыша в точности (+0/−1), его ценность —
   формулировки для ученика.
5. **Модель доверия** (`ml/`): логистическая регрессия на 6 признаках (вердикт, спор с ключом, разборчивость, тревога
   без названных ошибок, ответ «рядом с ключом», нет ключа), среднее 50 моделей кросс-фита; порог Learn then Test
   (α = 2%, δ = 0,1).
6. **Список задач** в проверку берётся из разметки (в оценке) или из задания репетитора (`--scope-file`, в работе).

## Данные

- 118 размеченных работ 19 учеников: dev — 107 работ, 1 702 задачи (374 с ошибкой); test3 — 11 работ, 139 задач (23).
  Первые два test использованы и переведены в dev. Ещё 8 сдач исключены из test3 до запуска (физика, решение по
  подсказкам в переписке, два задания с одинаковыми номерами) — data/private/test3_rows/excluded.json.
- **Разметка**: по пометкам проверяющего (фото с цветной ручкой, комментарии), переведённым в таблицу с помощью LLM по
  `LABELING_RULES.md` и `rules/policy.csv`; спорные места решала Ксения. Контроль: аудит по независимому ключу, разбор
  промахов, история правок (`leakage_audit.py`) и чувствительность метрик к ним (`label_sensitivity.py`).
- **Ключ ответов**: решён независимо от разметки и решений учеников (SymPy / вручную / таблицы ответов). Сборники
  ответов репетитора (data/tutor_keys/, нужны `compare_tutor_keys.py`) в репозиторий не входят — авторское право.
- **Режимы**: data/cards/modes.csv — exam (листы «Задание N», банк ФИПИ, варианты) и training (тренажёры, школьные).
- **Эталон распознавания**: 59 страниц (`data/gold/`, `ocr_eval.py`).
- Персональные данные: в API уходят только обезличенные фото (`redacted = 1`); имена, исходники и секреты не попадают в git.

## Как запустить

```
python3 -m venv .venv && source .venv/bin/activate      # для ноутбука; check.py — в обычном python3
pip install pandas scikit-learn matplotlib jupyterlab pillow pymupdf
echo "LLM_API_KEY=..." > .env                             # ключ OpenAI-совместимого API (в git не попадает)
python3 -m unittest discover tests                        # тесты, бесплатно

python3 features.py --include-unlabeled --out data/features_all.csv
python3 features_wide.py --features data/features_all.csv --out data/features_wide_all.csv --runs g_low_key

python3 ml/trust_exp_30.py                                 # модель доверия v5 (sklearn ≥ 1.9 — переобучить на своей машине)
```

## Воспроизводимость и честность

- Все ответы моделей кэшируются вместе с настройками (модель, уровень думания, версия промпта, ключ, фото); смешать
  прогоны с разными настройками нельзя — нужен `--tag`. Анализы воспроизводятся из кэша без запросов к API.
- Изменения системы проверялись парным сравнением на одних и тех же задачах (тест Мак-Немара + bootstrap по работам);
  для последних экспериментов правило перехода записывалось до запуска. Не принято 5 из 7 изменений (EXPERIMENTS.md).
- Всё, что выбрано по данным dev, помечено в ноутбуке. Вложенная кросс-валидация покрывает обучение, порог и выбор
  между наборами признаков v1/v2; сам признак «тревога без названных ошибок» придуман после разбора ошибок всего dev —
  это проверит только test.
- Test: протокол с гипотезами H1–H4 заполнен до запуска, код, разметка и модель доверия замораживаются хэшами и
  git-тегом; `check.py` и `ml/apply_trust.py` не запустятся на test при изменённых файлах или настройках, а
  `freeze_test.py` — если число задач и ошибок test в разметке не совпадает с протоколом.

## Ограничения

- **Условие задачи обязательно.** Без него проверка почти бессильна (test3: 15% совпадения); система должна
  останавливаться на входе и просить лист заданий.
- Мало ошибок в test3 (23, из них 15 в работах с условием) — интервалы широкие; разметка одной моделью (Claude) по
  пометкам проверяющих, независимая переразметка не сделана.
- Модель доверия обучена на вердиктах с офлайн-разметкой ситуаций (Claude), а работает с разметкой Gemini — на test2
  это давало больше пропусков (п. 23); на test3 пропусков не было, но и ошибок мало.
- Потолок задаёт распознавание: ошибки чтения цифр и «автоисправление» ошибок ученика не видны ни проверке, ни модели доверия.
- Стоимость: Gemini «думает» и на minimal; test3 стоил ≈ 72 ₽ на 11 работ (≈ 6,5 ₽ на работу с распознаванием условий).
- Ученики — от нескольких репетиторов, но выборка маленькая (19 учеников); перенос на другие темы требует проверки.
